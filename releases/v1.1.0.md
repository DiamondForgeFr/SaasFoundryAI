## What this version brings

Your coding agent can now hand ticket work to background agents sized to the task, one worktree per ticket, and SaaSFoundryAI tracks how those delegations turn out. AGENTS.md is now the single
instruction file every supported coding agent reads, and projects that relied on CLAUDE.md move to it when you run `sf update`.

### Delegated and routed work

- `sf update` generates one tier agent per routing tier for each declared coding agent, each with its own model and effort.
- `sf agents route` picks the tier for a kind of task from a shipped routing grid, and your manifest can override that grid for the project.
- `sf agents delegation` asks once whether tickets may be built by background agents and records the answer, shared with the team or local to one clone.
- Delegations are recorded automatically through Claude Code and Codex hooks. Routing adjusts from their outcomes within limits you can reverse, and `sf agents routing report` and `sf status` show
  what it did.

### Instructions and workflow

- `sf status` flags a CLAUDE.md that overrides AGENTS.md, an outdated Claude Code version, Codex instruction files near their size limit, the delegation consent and the routing state.
- Coding agents run the harness's read-only commands without asking for permission, and skills are copied only for agents that cannot find them on their own.
- AI Testing runs the project's declared local CI pipeline, posts its progress on the ticket's pull request, and a ticket moves to Done when its pull request is merged.
- Non-interactive setup lets you choose the workflow branches and attaches or creates the GitHub Projects board. An empty repository can be bootstrapped through its first ticket.

### SRS and generated projects

- `sf srs apply-update` changes an existing functional requirement in place, with a `--dry-run` preview.
- `sf srs spawn` reuses tickets that already exist, fills Story and Epic bodies from the SRS pages, puts every ticket on the board with a complexity label, and an `unlink-subtask` command is
  available.
- Generated applications build production images on the Node version their `.nvmrc` declares, deploy only after their tests pass, and present your project's name instead of SaaSFoundryAI.
- Generated projects pass the production dependency audit again.

This version also fixes command-line flags that were ignored, SRS content that was silently dropped, board problems on personal accounts, and updates that stopped on conflicts.
