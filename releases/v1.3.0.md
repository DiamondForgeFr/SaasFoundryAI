## What this version brings

Kimi Code now works as a coding agent next to Claude Code, with its own routing and tier agents. The guard now refuses shell lines it cannot check, such as substitutions, loops, chains and interpreter
heredocs, and tells the agent how to split them into lines it can check.

### Coding agents and workflow

- Kimi Code runs through its own profile and has its own tier agents. Each route names the model alias it uses.
- All coding agents get the same guidance on a UI ticket. A UI ticket cannot go to the developer's review until its mockup is validated.
- You can set the shell guard to refuse, warn or off. `sf status` shows the current mode, and `sf update` points it out.
- `sf status` names the workflow preset and shows which CLI the hooks reach, flagging one too old to run them. `sf workflow show` lists statuses by name.
- Git hooks refuse placeholder tickets and unnamed branches, so an agent cannot deliver work outside the workflow.

### Creating and updating projects

- When `sf update` changes Prisma or the API client codegen, it regenerates the committed clients. It also offers to resolve the lockfile again when pinned versions change.
- `sf new` makes one first commit that includes the harness and the manifest.
- When `sf workflow use` switches presets, it removes the previous preset's files and keeps every declared workflow field.
- Generated CI builds the web app before its end-to-end tests and passes from the first commit.

### Generated application

- Inviting a user who is already active is refused with a clear error. Deleting a role that is still assigned is refused with a message that names who holds it.
- Account admins can create entity-type roles and extend them up to what the entity type allows. Pending invitations count as places where a role is in use.

Also fixed: `sf update` on project names with uppercase letters, `sf feedback bug --auto-repro` on full projects, replies to PR review threads, generated git hooks under `sh` and on a detached HEAD,
stale cached web builds, dev-server imports from shared-config, duplicate Stories and changed milestones on `srs spawn` re-runs, and the generated API's production audit.
